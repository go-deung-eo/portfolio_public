배경

사내 에이전트 PoC는 OpenClaw를 프런트로 쓴다. 모델을 고를 때 /v1 엔드포인트 벤치마크는 페르소나, 툴 라우팅, 세션이 함께 도는 실제 동작을 대변하지 못한다. 그래서 각 턴을 openclaw agent --json으로 구동해 에이전트 스택 전체를 채점하는 하네스를 만들었다.

접근

과제는 코드 밖 tasks/bank.json에 두고 chat, tool-web, tool-exec 세 버킷을 영어와 한국어로 같은 내용으로 냈다. pass@1은 첫 시도에 깨끗이 성공한 경우만 인정한다. 최종 답이 맞아도 아래 조건 중 하나라도 있으면 실패다.

tasks/bank.json ─▶ runner ─▶ openclaw agent --json ─▶ 게이트웨이(페르소나·툴·세션) ─▶ vLLM
 chat / tool-web / tool-exec × EN·KO                                         │
                                                                             ▼
FAIL 조건: 턴 에러·타임아웃 | 불완전한 툴 호출 | 툴 마크업이 본문에 누출
           | 툴 에러 후 재시도로만 복구 | 툴 과제인데 툴 미호출
기록:      엔드포인트 프로브(서빙 설정) + 세션 .jsonl + 타임스탬프 결과 번들

1차 도중 세 모델의 결과 파일이 지워졌다. 세션 .jsonl 트랜스크립트에서 결과를 다시 만드는 파이프라인을 작성했고, 원본이 남아 있던 다섯 모델의 점수를 개수와 버킷까지 그대로 재현(5/5)해 파이프라인을 먼저 검증한 뒤 썼다.

원인 규명

깨짐 토큰. Ministral 계열이 한국어 문장 중간에 키릴·아랍·한자 토큰을 섞어 냈다. 원래 실행은 샘플링 옵션 없이 요청했고, 이 모델의 generation_config.json에는 샘플링 값이 없다. 이 경우 vLLM은 temperature 1.0, top_p 1.0, top_k −1을 쓴다. 온도만 바꾼 통제 실험으로 확정했다.

ministral-3-8b 한국어 생성, top_p 1.0, top_k −1. 횟수는 GB10 기준이며 RTX 6000 Ada에서도 같은 경향
temperature결과
0 (greedy), 0.7정상
1.0 (서버 기본값)깨짐 3/4
1.3 이상전부 깨짐, 온도에 따라 단조 증가

토크나이저(한국어 토큰 ID가 바이트 단위로 동일), vLLM 버전(0.13, 0.20.1, 0.23), GPU 아키텍처, 파서, 27 KB 오염 프롬프트는 각각 정상 재실행으로 배제했다. 조치는 --override-generation-config로 greedy를 강제하는 것이다. 툴 마크업 누출도 같은 현상이 툴 호출 위치에서 나타난 것이었다. BF16 변형이 기본 빌드보다 약 5배 많이 누출했고(37·36건 대 6–9건), 강제 temperature 1.3에서도 top_k ≤ 50이나 min_p ≥ 0.02로 절단하면 0건이 됐다.

샘플링 그리드. temperature × top_p × top_k 5×5×5 = 125조합(118개 채점)마다 서버를 다시 띄워 tool-exec 40과제를 돌렸다. greedy가 최선이었고, top_k와 top_p는 점수를 움직이지 않았다. 앞서 낸 "top_k 20이 최적"이라는 결론은 셀당 ±2/40 노이즈로 판명돼 철회했다. 4개 과제는 fixture 파일이 없어 무효로 빼고, greedy 점수를 27/36(75%)으로 고쳐 보고했다.

고정 래퍼 대 LLM 주도. 로컬 파일 열기 144+48회 시행에서 pass@1은 방식 간 차이가 없었다. 차이는 꼬리 지연이었다. 고정 래퍼는 최대 27.2 s였고, LLM 주도 방식은 성공한 시행에서도 174.8 s 타임아웃까지 갔다. open이 아무 출력 없이 rc=0으로 끝나면 모델은 이를 실패로 읽고 재시도를 반복했다. 조용한 빈 성공은 에러보다 나쁘다.

프롬프트 다이어트. 게이트웨이와 vLLM 사이의 캡처 프록시로 실제 전송되는 첫 요청을 떠 보니 코어, 번들 스킬 카탈로그(32%), 툴 스키마, 워크스페이스 파일의 4층이었다. 카탈로그를 끄고 설정 스키마에 없는 코어 프롬프트 모드는 배포 파일을 패치해 6,829 → 2,090 토큰(−69%)으로 줄였다. Qwen3-8B에서 시나리오 15/15턴이 호스트 ground truth 기준으로 통과했다.

시행착오

깨짐 토큰은 처음에 토크나이저 모드, 다음엔 GB10 커널 결함, 그다음엔 사라진 의존성 빌드 탓으로 결론 냈다. 셋 다 틀렸다. 원래 실행에 샘플링 옵션이 "없었다"는 사실을 확인한 뒤에야 서버 기본값이 변수로 보였다. 무료 검색 API 키가 400을 내서 2차 라운드에서 web 버킷을 뺐다.

배운 점

생성 설정이 비어 있는 모델은 서빙 엔진의 기본값으로 돈다. 평가 결과에는 실제 적용된 샘플링 값을 함께 기록해야 한다. 엄격한 채점은 무효 과제와 노이즈도 드러내므로, 점수보다 실패 사유 분포를 먼저 본다.
